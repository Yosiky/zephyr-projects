## Текущий урок: 16 — чистый parser команд

### Цель

Отделить решение «какая команда введена» от UART и вывода текста. Чистая
функция parser не зависит от Zephyr, устройства UART, `atomic_t` или глобальных
переменных; это сделает её простой для unit-тестирования.

### Задание

Создайте `15_command_parser` как копию `14_uart_commands`. Перед переносом
исправьте базовый UART-цикл: ограничение `COMMAND_MAX_SIZE - 1`, терминатор без
`length++`, игнорирование `\n` и echo backspace только при `length > 0`.

Создайте `src/command_parser.h`:

```c
#ifndef COMMAND_PARSER_H
#define COMMAND_PARSER_H

enum command_id {
    COMMAND_HELP,
    COMMAND_STATUS,
    COMMAND_UNKNOWN,
};

enum command_id command_parse(const char *text);

#endif
```

Создайте `src/command_parser.c`:

```c
#include "command_parser.h"

#include <string.h>

enum command_id command_parse(const char *text)
{
    if (strcmp(text, "help") == 0) {
        return COMMAND_HELP;
    }

    if (strcmp(text, "status") == 0) {
        return COMMAND_STATUS;
    }

    return COMMAND_UNKNOWN;
}
```

В `CMakeLists.txt` добавьте `src/command_parser.c` к `target_sources()`. В
`main.c` замените поиск в массиве `commands` на `switch (command_parse(command))`.
Только `main.c` решает, какой текст вывести и как получить `dropped`.

Проверьте в QEMU команды `help`, `status`, пустую строку и `unknown`.

### Проверка понимания

1. Почему `command_parse()` не должна получать `const struct device *uart`?
2. Почему счётчик `dropped` не должен читаться внутри parser?
3. Как такой parser можно протестировать без QEMU и без запуска Zephyr?

### Результат проверки

`command_parser.c` не зависит от Zephyr и правильно подключён в CMake. В
`main.c` ещё нужно заменить `command[length++] = '\0'` на
`command[length] = '\0'`: иначе после 31 символа Enter записывает терминатор
за границы `command[32]`. Также игнорируйте `\n` и echo backspace выполняйте
только при `length > 0`. Для `status` используйте `atomic_get()`, если команда
показывает текущее значение, а не намеренно сбрасывает интервал счётчика.

## Журнал занятий

### 1–2. Потоки и планировщик — 2026-08-08

- Создано `01_threads` для `qemu_riscv64` с `K_THREAD_DEFINE`.
- Меньшее числовое значение приоритета означает более высокий приоритет.
- `k_msleep()` блокирует текущий поток; равный приоритет не задаёт порядок.

### 3–5. Очереди сообщений — 2026-08-08

- Освоен `k_msgq`: `k_msgq_get()` пишет данные по указателю, а `0` — код успеха.
- При переполнении `K_NO_WAIT` возвращает ошибку; `k_msgq_purge()` явно
  отбрасывает устаревшие сообщения.

### 6. Mutex — 2026-08-09

- Mutex защищает критическую секцию; Zephyr допускает рекурсивный захват
  владельцем, но каждому lock соответствует unlock.

### 7. Semaphore — 2026-08-22

- Semaphore передаёт событие, а не данные; максимум 1 объединяет сигналы.

### 8–10. Таймеры и workqueue — 2026-08-22

- Callback `k_timer` выполняется в контексте прерывания и должен быть коротким.
- `k_work_submit()` переносит работу в system workqueue; долгий handler
  задерживает другие её задачи.

### 11–15. DeviceTree и Kconfig — 2026-08-22

- Kconfig определяет параметры сборки, `prj.conf` задаёт `CONFIG_*`.
- DeviceTree описывает оборудование; освоены `DT_CHOSEN`, `DT_ALIAS`,
  `DT_NODELABEL`, `DT_PROP` и `DEVICE_DT_GET`.

### 16–18. Heap и FIFO — 2026-09-03

- `k_heap_alloc(..., K_NO_WAIT)` возвращает указатель или `NULL`.
- `k_fifo` передаёт указатели без копирования; владелец меняется producer →
  FIFO → consumer.
- Ранний free создаёт use-after-free, отсутствие free — утечку памяти.

### 19–20. Slab и FIFO — 2026-09-19

- `k_mem_slab` даёт пул одинаковых блоков без фрагментации heap.
- Пул из четырёх блоков ограничивает число одновременно выделенных сообщений.
- Consumer возвращает блок через `k_mem_slab_free()`.
- В проверенной реализации исправлен счётчик consumer. При отказе allocation
  producer должен применить retry-policy с задержкой, чтобы не создавать busy loop.

### 21. Структуры в `k_msgq` — 2026-09-20

- `k_msgq` копирует структуру в статический буфер, поэтому передача не требует
  динамического выделения, освобождения или правила владения указателем.
- При `K_NO_WAIT` producer может отбросить сообщение при полном буфере.
- При `K_FOREVER` producer блокируется до освобождения места consumer-ом;
  сообщения сохраняются, но фактический период producer увеличивается.

### 22. Выбор IPC-механизма — 2026-09-20

- Для переменных команд выбран `k_fifo` + `k_heap` с передачей владения
  producer → FIFO → consumer.
- Уточнено: `k_msgq` не отбрасывает данные автоматически; поведение при
  заполнении определяется timeout/policy вызова `k_msgq_put()`.
- Требуется уточнить backpressure и ограничение нагрузки в сценариях датчика
  и ISR до перехода к драйверам.

### 23. Политики перегрузки IPC — 2026-09-20

- Для обязательной доставки ошибка переполнения недостаточна сама по себе:
  нужен backpressure или гарантированный внешний буфер.
- Для потока кадров выбор между отбрасыванием новых и старых данных зависит от
  смысла: полнота истории либо приоритет самого свежего кадра.
- Этап «Память и IPC» завершён; следующий этап — прямое использование UART.

### 24. UART polling API — 2026-09-20

- Console UART получен через `DT_CHOSEN(zephyr_console)` и проверен через
  `device_is_ready()`.
- `uart_poll_in()` возвращает один доступный байт без ожидания; polling
  масштабируется плохо при активном или скоростном приёме.
- `k_msleep(10)` блокирует текущий поток, но допустим в thread: scheduler
  запускает другие потоки. В ISR и timer callback спать нельзя.

### 25. Проверка UART ISR — 2026-09-20

- Сборка `13_uart_irq` для `qemu_riscv64` проходит.
- ISR корректно читает UART и передаёт байты в очередь с `K_NO_WAIT`.
- Усложнение требует доработки: timer callback не должен печатать/сбрасывать
  счётчик, а главный поток должен блокироваться на `k_msgq_get(K_FOREVER)`.

### 26. Доработка UART ISR — 2026-09-20

- Исправлены ISR и главный поток: atomic-счётчик, очередь глубиной 16 и
  блокирующее получение из очереди.
- Осталось изменить период reporter с 10 секунд на 1 секунду.

### 27. UART interrupt-driven API — 2026-09-20

- ISR читает UART FIFO и передаёт байты в `k_msgq` с `K_NO_WAIT`.
- Главный поток блокируется на `k_msgq_get(K_FOREVER)` и выполняет echo.
- Atomic-счётчик потерь корректно увеличивается в ISR. Десятисекундный
  reporter и ненулевой return при неготовом UART оставлены намеренно для теста.
- Следующий шаг: собрать UART-байты в строку и реализовать команды `help` и
  `status` в главном потоке.

### 28. Проверка UART-команд — 2026-09-20

- Сборка `14_uart_commands` проходит.
- Команды `help` и `status` вынесены из ISR в главный поток.
- Требуется исправить off-by-one при терминаторе строки и обработать `\n` /

### 29. Переход к parser команд — 2026-09-20

- UART ISR и главный поток оставлены транспортным слоем; обработка команд
  переносится в чистую функцию без зависимостей от Zephyr.
- Исправления границы строкового буфера остаются обязательной частью нового
  приложения.

### 30. Проверка parser команд — 2026-09-20

- Parser не зависит от UART или Zephyr и добавлен в `target_sources()`.
- В основной UART-цикл перенеслись off-by-one при нулевом терминаторе,
  неигнорируемый `\n` и echo пустого backspace; их нужно исправить до тестов.
